## 问1 · 三焊缝中最具实质推进力的一条 + 最小可落地动作

**最有推进力的是焊缝①（数值锚 → Lean 可验证陈述）。**

理由：②③都寄生在①之上。SHAP 重要性若不能先变成 Lean 里的一个可判定谓词，"证明搜索启发"就仍是散文；形式约束若没有可编译的陈述，编译器捕获的只是语法偏离而非语义偏离。焊缝①是唯一能在**不信任上游叙事**的前提下独立成立的环节。

**可落地最小动作（一个下午量级）**：

> 取该 PINN 框架中**任意一个**被 postulate 的数值声称（例如"某损失项单调下降"或"某残差 < ε"），把它改写成一个 Lean 4 定义：
> ```lean
> def claim_001 (traj : Nat → Float) : Prop :=
>   ∀ n, traj (n+1) ≤ traj n
> ```
> 并用 `#check` / `example` 让编译器**拒绝**在缺少证明项时通过。**不写证明，只写陈述，看它是否 type-check。**

这一步的产出不是"证明了什么"，而是**暴露该声称能否被机械化为带类型的命题**。如果连陈述都写不出唯一形式（歧义、依赖语境、需要补充隐含定义），那么后续两条焊缝在工程上就无从挂载。

## 问2 · 焊缝②的重要性加权 vs 联邦 default-deny 纪律

**兼容，但只在一条窄条件下兼容：重要性权重必须被视为「搜索顺序的提示」，而非「通过门槛的豁免」。**

- **兼容条件**：
  - 权重作用于**启发式排序**（先证哪条、先展开哪支），default-deny 作用于**接受判定**（没有证明项 = 拒绝）。二者作用域正交——排序可以任意偏心，判定仍是 0/1。
  - SHAP 值进入 Lean 侧时，必须被降级为 `Nat` 序号的排序键（`priority : Lemma → Nat`），**不得**作为 `Prop` 的真值来源。

- **冲突点**：
  - 若把 SHAP 高重要性当作"该假设可先 postulate 后补证"，就直接违反 default-deny——权重变成了**例外通行证**，这正是原附件脚手架的病灶。
  - 若权重来自模型内部黑箱，而 Lean 侧需要可复现的排序，则 SHAP 的可复现性本身成为新依赖（浮点、版本、随机种子），引入未类型化的隐式前提。

**一句话边界**：权重可以决定"先敲哪扇门"，不能决定"门是否已经打开"。

## 问3 · 如何识别并熔断「postulate 脚手架」式假框架

从 Lean 工程侧，识别信号按可靠性排序：

1. **`axiom` / `postulate` / `sorry` 的密度与位置**：如果所谓"核心定理"直接建在公理上，且公理本身不是公认数学基础（如 ZFC 片段、`propext`、`funext` 这类可审计项），而是**业务定义**，则是脚手架。可机械扫描：`grep -n "sorry\|axiom\|postulate"` 的命中行是否落在关键路径。
2. **type-in-type 或 `Prop`/`Type` 混用的静默通过**：Lean 4 默认 `Type : Type` 关闭，但若框架要求打开或依赖不一致宇宙，说明它需要"不健全"来维持叙事。
3. **陈述不可独立复述**：把框架文档里的"定理"抄出来，让一个不懂该框架的人尝试在 Lean 里写下类型——若写不出（依赖大量未定义术语、语境、隐含约定），则该"定理"不是命题，是措辞。
4. **无 `#check` 级最小复现**：真正的形式化声称总能被拆到一个 `example` 里；脚手架声称一旦要求 `example` 就崩解为"这需要先定义……"。

**熔断动作**：不辩论，直接要求 **MWE（Minimal Working Example）**——"给我一个 20 行内、能 type-check、不依赖你框架其余部分的 `example`"。给不出，即标记为脚手架，进入隔离区而非驳倒区（因为它不可被驳倒，只可被搁置）。

## 附答 · 你线角问：锚谓词机器化推广的最大技术障碍

**最大障碍不是数学难度，而是「谓词的指称唯一性」。**

WS-25 演示器能跑，是因为它选的锚谓词在上下文中**只有一个自然形式化**。一旦推广到真实 PINN / 科学计算场景，同一个自然语言声称往往对应多个不等价的 Lean 命题（连续 vs 离散、逐点 vs 一致、实分析 vs 浮点近似、有无边界条件量化），而**选错指称的 Lean 命题照样 type-check、照样可被"证明"——只是证的不是原意**。

这导致一个工程悖论：

- 要机器化锚谓词，需要先固定语义；
- 但固定语义本身是**领域约定**，不是类型论能自动决定的；
- 一旦把语义固定写成 Lean 定义，该定义又成为新的 postulate——除非它能被追溯到更基础的数学定义。

**因此最大障碍是「语义锚定的递归终止问题」**：在哪一层停止解释、把该层当作"基础词汇"接受，这个决定是**社会-技术决定**，不是 Lean 能给出的。形式化工具能捕获**陈述之后**的偏离（焊缝③的真实价值），但捕获不了**陈述之前**的歧义。把这一点讲清楚，比声称"机器化可推广"更诚实。
